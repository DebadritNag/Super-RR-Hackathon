## Decisions made in this plan (not left to the implementer)

1. **Package layout.** New package `app/phase6/` mirroring `app/phase5/` (constants, store, outputs, lockguard, pipeline reuse). Phase 6 imports `app.phase5.pipeline.Study`/`load_study`, `app.phase5.reliability` (`CellData`, `from_cell`, `boot_moments`, `decompose_moments`, `reml_tau2`, `half_masks`, `half_stats`, `split_half`, `sb`, `reliability_by_opportunity`, `required_sample`) and `app.phase4.shrink` rather than copying them. Rationale: Phase 5 already built tested machinery; the new work is additional estimators and new windows.
2. **Primary window.** "Full available verified historical data" = the existing Phase 5 `PRE_TEST` window (TRAIN+VALIDATION, 723 matches, 2022-01-22 to 2025-12-19), minus the 42 late-dated T20I matches where Phase 5 already excludes them. TEST outcomes cannot be used for tuning, and Phase 5's `load_study` already drops TEST rows (`drop_test_rows`). Record this as open decision OD-1 in the register: "primary window is pre-test only; TEST outcomes remain unopened". Do not widen it.
3. **Definition comparison is gated by a pre-declared criteria file.** `config/phase6_selection_criteria_v1.json` is written and hashed (`data/reports/phase6_selection_criteria_hash.json`) BEFORE any definition-comparison code runs. The comparison refuses to run if the file or its recorded hash is missing, and refuses to write results if the hash differs from the one recorded before. No criterion may reference player ids, ranks, or Top-10 membership.
4. **Estimator set for between-player variance.** (a) method of moments with floor (the Phase 4 `k_from_children` basis), (b) normal-normal REML (`reml_tau2`) and ML, (c) beta-binomial (binary pressure streams) and gamma-Poisson (count streams) method-of-moments/ML marginal likelihood, (d) match-clustered bootstrap variance components (resample matches, reuse `en.cell_weights`/`match_weights`), (e) split-covariance (odd/even half means; model-free, already in `rb.split_cov_rows`). Diagnostics for the floor: residual-variance heteroscedasticity (variance of residual by player-ball-count tercile), overdispersion (Pearson dispersion by match clustering, intraclass correlation of balls within matches/innings), and a power/detectability check (reuse `rb.simulate_detectability`).
5. **Gate safety.** The 0.5 data-weight gate is never edited. The options report computes, for each legitimate option, the data weight that results and which of the 48 contexts / 4 format-role cells would pass 0.5. Lowering or bypassing the gate is not an option row and a test asserts so.
6. **Cache key scope.** `RankingCache.get_or_compute` gains a `scope` (`"internal"`/`"public"`) and `lock_version` component and returns deep copies on every get/put (`copy.deepcopy`). Gate state is already recomputed on read; add the gate-config version and a hash of failing-gate ids to the key as "gate-relevant state".
7. **Public descriptive schema.** `/players` and `/players/{player_id}` keep a public descriptive response, but their response models become new classes `PublicPlayerRow`/`PublicPlayerListResponse`/`PublicPlayerDetailResponse` that contain only identity, nationality, international_status (+ verification fields), group, squad_role, match counts, `classification_version`, plus the experimental flags. `eligible_scopes`, `conflict_flag` and any score/rank/eligibility field are removed from the public model. `/players/{id}/profile` and other routes that expose scores stay internal (token-protected) or disabled; verify in `app/api/v1/routes.py` which are on the `public` router before moving anything, and move score-bearing ones to the internal router only if they are currently public. Record each moved route in the cleanup report.
8. **Three-status wording.** Real values are `VERIFIED_CAPPED`, `DERIVED_CAPPED`, `UNKNOWN`. `VERIFIED_UNCAPPED` remains in code as a disabled placeholder constant (the strict-uncapped filter and override mechanism stay), but `ClassificationStatus` in `app/schemas/phase5.py` and `classification_values` in the capabilities response list the three real values only. Placeholder is exposed in a separate field `disabled_placeholder_values: ["VERIFIED_UNCAPPED"]`.
9. **Season robustness and recent-form are separate artifacts** with their own tables (`p6_recent_*`, `p6_season_*`), never merged into primary outputs, each row labelled `RECENT_FORM_SEPARATE_ANALYSIS` or `ROBUSTNESS_NOT_VALIDATION`.
10. **Open decisions to record, not block on:** OD-1 primary window is pre-test; OD-2 whether the 2024+/2025+ windows should have their own frozen eligibility thresholds (this plan uses Phase 4 frozen ball thresholds scaled by each window's own ratio and labels them provisional); OD-3 whether the user wants a new hold-out collected.
